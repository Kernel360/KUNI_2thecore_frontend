# 🔒 WebSocket 레이트 리미터 테스트 가이드

## 🧪 **테스트 방법: 초당 2회 제한 확인**

### **1. 브라우저 개발자 도구에서 확인**

```javascript
// F12 → Console 탭에서 실행
// 레이트 리미터 동작 확인용 테스트 코드

// 1초에 5번 연속 호출해서 레이트 리미터 테스트
for (let i = 0; i < 5; i++) {
  setTimeout(() => {
    console.log(`테스트 호출 ${i + 1}/5`);
    // 실제 WebSocket 메시지가 올 때 레이트 리미터가 작동함
  }, i * 100); // 100ms 간격으로 5번 호출
}

// 예상 결과: 처음 2번만 처리되고 나머지 3번은 차단됨
// Console에 "레이트 리미터: 초당 2회 초과로 요청 무시됨" 메시지 확인
```

### **2. Network 탭에서 WebSocket 메시지 빈도 확인**

1. **개발자 도구 → Network → WS (WebSocket) 탭**
2. **페이지 새로고침** 후 WebSocket 연결 상태 확인
3. **메시지 타임스탬프** 간격 관찰:
   - ✅ **정상**: 메시지가 0.5초(500ms) 이상 간격으로만 표시
   - ❌ **문제**: 메시지가 0.5초 미만 간격으로 계속 표시

### **3. Console 로그에서 레이트 리미터 작동 확인**

개발환경에서 다음 메시지들이 표시되어야 함:

```javascript
// ✅ 정상 처리되는 메시지
'차량 12가1234 WebSocket 연결됨';
'차량 12가1234 실시간 위치 업데이트: {...}';

// 🔒 레이트 리미터가 작동하는 메시지 (초당 2회 초과 시)
'레이트 리미터: 초당 2회 초과로 요청 무시됨';
```

### **4. 성능 지표 확인**

**Performance 탭 → Memory 서브탭**에서:

- CPU 사용률이 이전보다 현저히 낮아짐
- WebSocket 메시지 처리 빈도가 안정적으로 유지됨

```
CPU Usage: 낮음 (안정적 메시지 처리)
```

## 🚨 **문제 해결 방법**

### **레이트 리미터가 작동하지 않는 경우:**

1. **하드 새로고침**: `Ctrl + Shift + R` (캐시 무시)
2. **빌드 재실행**: `npm run build` 후 다시 테스트
3. **WebSocket 연결 확인**: Network → WS 탭에서 연결 상태 점검
4. **브라우저 캐시 삭제**: 개발자 도구 → Application → Storage → Clear storage

### **레이트 리미터 로그가 안 보이는 경우:**

```javascript
// Console에서 수동으로 테스트
// 개발환경에서만 로그가 표시됨을 확인
console.log('NODE_ENV:', process.env.NODE_ENV);
// 'development'가 아니면 로그가 표시되지 않음
```
